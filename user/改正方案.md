第 2 步：I2C 超时 + 返回值检查（先做这个，否则后面调试一卡死就找不着北）


/* i2c.c 里加一个带超时的等待，把 16 处裸 while 全换掉 */
static uint8_t I2C_WaitFlag(I2C_TypeDef *I2Cx, uint32_t Flag, FlagStatus State, uint32_t TimeoutUs)
{
	uint64_t t0 = GetUs();
	while(I2C_GetFlagStatus(I2Cx, Flag) == State)
	{
		if(GetUs() - t0 > TimeoutUs) return 1;   /* 1 = 超时 */
	}
	return 0;
}
普通位置超时取 5~10ms（400kHz 下一帧只要几百 µs）；返回值加一个 -3。
两处在 __disable_irq() 临界区内的等待（i2c.c:168、i2c.c:308）不能调 GetUs()（它内部会重新开中断），改用纯循环计数限次。
超时后恢复：I2C_GenerateSTOP → 失败计数连续 N 次就 I2C_DeInit + 重新 I2C_Init，再不行就手动打 9 个 SCL 脉冲解锁从机。
App_MPU6050_Update 里判返回值，失败就保留上一帧数据（static 缓存），别让栈垃圾进姿态环。

第 5 步：转向环（改 app_balance.c，替换 238-239 行）


#define BAL_WHEEL_TRACK  (0.095f)   /* 左右轮中心距，m，实测填 */
#define BAL_KP_STEER     (0.15f)    /* 轮速差纠偏 */
#define BAL_KD_YAW       (0.03f)    /* 陀螺阻尼 */
#define BAL_STEER_MAX    (8.0f)     /* 转向量限幅 rad/s */

/* 约定：steer > 0 = 左转（右轮快） */
steer  = BAL_KP_STEER * (spd_L - spd_R);            /* 左轮快 = 车在右偏，给左转量 */
steer -= BAL_KD_YAW * App_Attitude_GetYawRate();    /* 抑制偏航角速度突变 */
steer += steer_cmd;                                 /* 遥控转向指令，无遥控时为 0 */
限幅 ±BAL_STEER_MAX;

App_Motor_SetTarget_L(omega_ref - steer);
App_Motor_SetTarget_R(omega_ref + steer);
两个要注意的点：

车轮线速度按"正 = 前进"统一了符号（app_encoder.c:300 和 app_pwm.c:120-131 都做过补偿），所以 spd_L - spd_R 的符号不需要额外标定；但陀螺那一路的符号必须实测（手转车身，看轮子是帮着转还是顶着转，反了就翻 BAL_KD_YAW 的号）。
转向是等量反向叠加，平均值不变，所以不会污染速度环的 x_dot 重建——这套结构可以放心加。
App_Attitude_GetYawRate() 需要新增（在 app_attitude.c 里）：return (ATT_GZ - gz_bias) * ATT_SIGN_YAW;，别直接用 App_MPU6050_GetGz()（没扣零偏）。
第 6 步：看门狗 + 堵转 + 限幅
void IWDG_Init(void)   /* LSI≈40kHz，64分频 + 重装1000 ≈ 1.6s */
{
	IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);
	IWDG_SetPrescaler(IWDG_Prescaler_64);
	IWDG_SetReload(1000);
	IWDG_ReloadCounter();
	IWDG_Enable();
}
必须放在 1 秒陀螺校准之后（或把校准循环拆开喂狗），否则每次上电都会被复位。
调试时用断点会被 IWDG 打断：加 DBGMCU->CR |= DBGMCU_CR_DBG_IWDG_STOP;（调试期间冻结）。
堵转判据（App_Motor_Update 里）：fabsf(duty) > 60% 且 fabsf(spd) < 3 rad/s 持续 300ms → 置故障位、App_PWM_Set_L/R(0)，故障位在 App_Motor_Reset() 里清。
omega_ref 没有上限（app_balance.c:235 是纯积分），建议加 ±40 rad/s 限幅，防止模型偏置导致目标轮速无限涨。
第 7 步：串口遥控（新建 App_USART2_Init()：PA2 复用推挽 / PA3 上拉输入 / 115200 / RCC_APB1Periph_USART2，波特率按蓝牙模块实际值填）。接收必须走中断——usart.c:160 的 My_USART_ReceiveLine 是阻塞的，在任务里调会把控制环拖住整个 Timeout。中断里收字节进行缓冲，由一个 20~50ms 的任务解析成 App_Balance_SetTargetSpeed() / App_Balance_SetSteer()；同时加一个"500ms 没收到指令就减速停车"的失联保护。

第 8 步：电池（可选，需要先决定硬件）

想要真正的电压表：得牺牲一个已占用脚（K3/K4 之一，或放弃 USART2 用 PA2/PA3），外加自己在 VIN 上加分压。
零硬件方案：用内部通道 ADC1_IN17（VREFINT），不需要任何引脚和外围。它测的是 LDO 输出的 3.3V——电池快没电时 LDO 退出稳压、3.3V 跟着掉，可以当"电池告急"报警用，但不是电量计（典型值 1.20V，误差 ±3%）。
现在这样直接返回 0 也不算错，至少不会误导上层。
建议的落地顺序
先做第 2 步（I2C 超时）和第 1 步（正式入口），这两步不做，后面每次调试都会变成"卡死还是翻车分不清"；然后第 4 步标定中位 → 第 3 步按键 → 上地跑通直线 → 第 6 步安全项 → 第 5 步转向 → 第 7 步遥控 → 第 8 步电池。
