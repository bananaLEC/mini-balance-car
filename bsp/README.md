# bsp/ — 板级驱动层（Board Support Package）

本目录下全部代码为**本项目自研**，依据公开数据手册与官方参考手册编写，
不含任何第三方驱动源码。

## 与旧实现的关系

重构前 `my_lib/` 下的底层驱动（`delay` / `usart` / `i2c` / `si2c` / `oled` / `qmath` / `spi` / `str_cmd`）
来源为 B 站「铁头山羊」，未附带任何开源许可证。本目录是它们的**重写替代**，
接口名与签名保持兼容，因此 `user/` 与 `test/` 无需改动。

`my_lib/` 现在只保留本项目自己写的三个模块：`task.*`（周期任务调度）、
`pid.*`（PID 控制器）、`button.*`（按键驱动）。

## 依据的文档

| 模块 | 依据 |
|---|---|
| `delay.*` | ARM **DDI 0337**（Cortex-M3 技术参考手册）— SysTick、DWT_CYCCNT、`SCB->SHP[]` |
| `usart.*` | ST **RM0008** 第 27 章（USART）；Keil MDK microlib 文档 |
| `i2c.*` | ST **RM0008** 第 26 章；ST **AN2824**；**ES096**（STM32F103 勘误手册） |
| `si2c.*` | NXP **UM10204**（I2C-bus specification） |
| `oled.*` | Solomon Systech **SSD1306** 数据手册 Rev 1.1 |
| `font6x8.*` | 本项目自行制作的点阵字模 |

## 两条 I2C 总线现在都是软件（位拆）I2C

| 总线 | 器件 | 引脚 | 半周期 |
|---|---|---|---|
| `mpu_si2c`（`user/app_mpu6050.c`） | MPU6050 | PB10(SCL) / PB11(SDA) | 3 µs |
| `oled_si2c`（`user/app_oled.c`） | SSD1306 OLED | PB8(SCL) / PB9(SDA) | 2 µs |

**为什么 MPU6050 也从硬件 I2C2 改成了软件 I2C**：STM32F1 的硬件 I2C 外设状态机
很难伺候，一旦被干扰打断就会锁存 `AF`/`BUSY` 等状态，必须靠「打时钟脉冲 + 复位外设」
才能拉回来，而现场表现是救回来没读几帧又失败、周而复始。软件 I2C 用 GPIO 打时序，
不存在「外设卡死」这一说 —— 某一次传输失败，下一个起始条件就是全新的时序。

`bsp_i2c.c/.h`（硬件 I2C 驱动）**保留在仓库里但当前无人调用**：链接器的
section GC 会把它整段丢掉，不占 Flash；留着是为了将来若把器件挪到走线很短的
板载总线上、想换回硬件 I2C 时不用重写。注意它带的总线抢救逻辑对硬件 I2C 才有意义。

### 软件 I2C 的代价：CPU 占用

位拆 I2C 是纯忙等，半周期直接换算成 CPU 占用。一轮 14 字节读取要
`14 字节 × 9 位 × 2 个半周期`，所以：

| 半周期 | 一轮 14 字节读取 | 占 5 ms 控制周期 |
|---|---|---|
| 3 µs（当前 MPU 设置） | 约 0.76 ms | 约 15% |
| 5 µs | 约 1.3 ms | 约 25% |

**别把半周期往小调**：既吃 CPU，又要求更好的走线与上拉。要提速应该先确认
SDA/SCL 上有 4.7 kΩ 上拉、线尽量短。
