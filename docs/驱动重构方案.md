# my_lib 底层驱动重构方案

> 目标：把 `my_lib/` 下属于「铁头山羊」的驱动代码全部替换为本项目自研实现，
> 解除版权风险；保留自己写的 `task.*` / `pid.*` / `button.*` 不动（仅跟随改一行 `#include`）。
>
> 状态：**待确认，尚未动代码。**

---

## 0. 先说结论：这件事能不能做到

**能做到，而且风险可控。**

理由有三条：

1. **被替换的都是「接口 + 寄存器操作」，本身思想不受著作权保护。**
   著作权保护的是「表达」——代码怎么写的、注释怎么写的、结构怎么组织的。
   保护不了「软件 I2C 要拉低 SCL」「I2C 发完地址要等 ADDR 标志」「OLED 初始化依次写 0xAE/0xD5/0xA8…」这些事实。
   我们用数据手册重新实现同样的功能，不抄它的代码与注释，就产生了一份独立的、著作权归你的新代码。

2. **项目已经证明可以完全脱离。** 全量审计后的实际依赖面比想象的小得多（见第 1 节）：
   - `math.h` 已经提供了 `atan2f`，**`qmath.c` 整个 341 行可以直接删掉**，不用重写；
   - `spi.*`、`My_USART_ReceiveLine`、`My_USART_ReceiveByte` **一个调用点都没有**，直接删；
   - OLED 那一大套 API（33 个函数）里，**实际只用到 9 个**，其余 24 个（画圆/画线/矩形/位图/剪切区/文本框/字体切换…）全部可以砍掉。

3. **我已经把工具链验证跑通了（这条很关键）。**

   | 项目 | 结果 |
   |---|---|
   | Keil MDK 工具链 | `D:\Keil_v5` 存在，armcc / armasm / armlink V5.06u7 均可用 |
   | UV4 命令行编译 | ❌ 崩溃（`0xC0000409`，当前沙箱下 UV4 GUI 起不来），**不能依赖，也不影响结论** |
   | armcc 直接编译 | ✅ 用工程同款参数（`--c99 --gnu -O1 --cpu Cortex-M3 -DSTM32F10X_MD`）逐个编译 |
   | 基线 | ✅ **29 个 .c 文件 0 错误 0 警告全部通过** |
   | armlink 链接复现 | ✅ 用 `Objects/template.lnp` + `template.sct` 链接，输出 **`Code=23516 RO-data=14444 RW-data=196 ZI-data=9188`，与 Keil 上次构建日志逐字节一致** |

   也就是说：**每改一个文件都能立刻编译验证，最后还能链接出完整固件并对比体积**，
   不需要你在 Keil 里手动试。这是这个方案敢动手的前提。

   > ⚠️ 唯一需要你配合的：UV4 起不来，最后一遍「在 Keil 里点 Build」请你自己点一次，
   > 因为链接器版本/工程配置的最终确认只有 IDE 能给出（不过 armlink 已经复现了同样结果）。

### 1.3 顺带发现的两个坑（重写时一并修掉）

1. **`i2c.h` / `si2c.h` / `spi.h` 三个头文件没有 include guard**（直接以 `#include "stm32f10x.h"` 开头）。
   现在没炸是因为它们只被包含一次，属于定时炸弹，重写时补上。
2. **`oled.c` 用了 `malloc()` 分配帧缓冲**（`OLED_Init` 里 `malloc(1025)`，还做了 `pBuffer++` 的偏移 hack）。
   工程链接选项是 `--library_type=microlib`，用的是 microlib 的堆。
   这是在安全关键的控制程序里引入堆依赖，重写时改成**静态帧缓冲**（或由调用方传入缓冲），
   既去掉堆，又省掉 microlib 堆初始化。

#### 字体怎么来（`oled_default_font.h` 的替换方案）

原文件由铁头山羊的 `bdf2c.exe` 从 BDF 字体生成，工具和生成结果都带他的署名。
**点阵像素数据本身是纯事实信息、不构成受保护的表达**，但为了彻底干净，方案是**自带字体表**：

- 采用 **6×8 像素、95 个可见 ASCII 字符**（0x20–0x7E）的紧凑点阵表，共 `95 × 8 = 760` 字节。
  相比原来的 BDF 方案（95 个字形 × 约 40 字节元数据 + 位图），**Flash 和代码量都大幅下降**。
- 字模数据自己生成／自行核对，用脚本渲染成图逐字检查（见 4.4 的验证手段），
  来源标注为「本项目自行制作」，不进 `THIRD_PARTY_NOTICES.md` 的第三方表。
- 若你想更省事、且接受注明出处：也可以用 **SIL OFL v1.1** 许可的开源字体
  （例如 Inter / IBM Plex Mono）由我写脚本转成点阵表——OFL 允许再分发，**只要保留版权声明**。
  这是「干净但需要署名」的选项；上面「自研 6×8 表」是「最干净、不依赖任何第三方」的选项。

## 3. 重构方案

### 3.1 接口策略：**函数名和签名一律不变**

这是本方案最重要的一个决定，理由：

- `My_I2C_SendBytes`、`OLED_DrawString` 这类**函数名是功能性标识，不受著作权保护**；
  签名的形态也由功能决定（「发 N 个字节」只能长这样），属于「思想与表达合并」的情形。
- **`user/` 和 `test/` 一行都不用改**，回归风险降到最低。
  如果改名，`main.c`、7 个 app 文件、6 个 test 文件、`app_oled.c` 都要跟着改，纯属自找麻烦。
- 真正体现「独立实现」的是**实现代码、注释、文件头、内部结构**——这些 100% 重写，
  并且注释按我们自己的中文风格重写（不是改几个字，是重新组织）。

> 如果你希望连函数名也换掉（比如 `BSP_I2C_Write` 风格），我可以做，
> 但请知悉代价：`user/`+`test/` 里约 40 处调用点和 10 个 `#include` 要同步改，多一轮回归。**见第 6 节 Q2。**

### 3.2 目录结构：新建 `bsp/`，旧文件相位出清

```
bsp/                     ← 新增：全部为本次自研
├── bsp_delay.c/.h       ← 替代 my_lib/delay.*
├── bsp_usart.c/.h       ← 替代 my_lib/usart.*
├── bsp_i2c.c/.h         ← 替代 my_lib/i2c.*
├── bsp_si2c.c/.h        ← 替代 my_lib/si2c.*
├── bsp_oled.c/.h        ← 替代 my_lib/oled.*
└── bsp_font6x8.c/.h     ← 替代 my_lib/oled_font.h + oled_default_font.h

my_lib/                  ← 保留（你自己写的）
├── task.c/.h
├── pid.c/.h
└── button.c/.h
```

**为什么放新目录而不是原地覆盖 `my_lib/`：**
1. 新旧并存，可以逐个模块切换、逐个验证，随时能回退到旧实现对比行为；
2. 全部验证通过后再一次性删掉旧文件，`git` 里能清楚看到「旧的删了、新的加了」；
3. `bsp/` 这个名字本身就表明了「板级支持包」，比 `my_lib/` 更专业。

**代价**：`task.c` / `pid.c` / `button.c` 里的 `#include "delay.h"` 要改成 `#include "bsp_delay.h"`，
三个文件各一行；`template.uvprojx` 的 include 路径要加 `.\bsp`。其余改动都在新文件里。

> 如果你更想原地覆盖 `my_lib/`，也能做，见第 6 节 Q1。

### 3.3 逐模块设计要点

#### (a) `bsp_delay` —— 地基，最先做

| 函数 | 实现要点 |
|---|---|
| `Delay_Init` | 配 SysTick：`RCC_GetClocksFreq` 取 HCLK → `LOAD = HCLK/1000 - 1`，开 TICKINT 和 ENABLE；中断优先级写 `SCB->SHP[7]`。**保留原有的「首次调用才初始化」幂等语义**（`main.c` 和多个模块都会调） |
| `GetTick` | 返回 ms 计数器（`volatile`） |
| `GetUs` | ms 计数 ×1000 + 读 `SysTick->VAL` 换算余数 |
| `Delay` / `DelayUs` | 死等时间戳；`DelayUs` 只在 `bsp_i2c` 抢救总线时用 |

**⚠️ 已知缺陷，重写时必须解决**：原 `GetUs()` 内部用 `__disable_irq()` / `__enable_irq()` 包住读数，
所以**在临界区里调它会意外开中断**——`i2c.c` 里因此专门写了 `I2C_WaitFlagCritical` 用循环计数绕过。
这是原实现的硬伤。两个可选方案：

- **方案 A（推荐）**：`GetUs()` 不用关中断，改用 **DWT->CYCCNT 周期计数器**（Cortex-M3 有）
  配合 SysTick 溢出计数，天然可重入，临界区里也能调。彻底消灭 `..._Critical` 特例。
- **方案 B（保守）**：保留原思路，但把临界区相关的等待统一改用「读两次 + 容错重试」，
  不再依赖「调用方不许在临界区调 `GetUs`」这条隐性约定。

#### (b) `bsp_usart` —— 最简单，先练手

- 阻塞式发送：逐字节等 `TXE`，全部发完等 `TC`（**等 `TC` 是原实现的正确之处，保留**）。
- `My_USART_Printf`：`vsnprintf` 到 128 字节栈缓冲。
  ⚠️ microlib 下 `%f` 走软件浮点、耗时数毫秒——**保留现有注释里「控制环内禁止调用」的警告**，这是关键约束。
- 接收三函数：`ReceiveByte` / `ReceiveBytes`（带 ms 超时）/ `ReceiveLine`（CR/LF/CRLF）。
  **零调用点，但接口保留**（`app_bluetooth` 有自己的中断环形缓冲，不依赖这个；
  留着是为了以后加有线命令行控制方便）。若你想更瘦，也可以直接删——见 Q3。

#### (c) `bsp_i2c` —— 风险最高，重点投入

要保留的语义（这些是功能正确性的关键，不是我抄来的结构）：

1. **返回值约定不变**：`0` 成功 / `-1` 寻址失败 / `-2` 数据被拒 / `-3` 超时。`app_mpu6050.c` 已经在判返回值。
2. **所有等待都带超时**（10 ms）。原实现是裸 `while` 死等，你后来打了补丁；新实现从一开始就是带超时的。
3. **`ADDR` 清标志必须先读 SR1 再读 SR2**——这是 ST 官方文档规定（D7），不这么做会卡死。
4. **单字节接收**：读 SR1/SR2 形成临界区 → 关 ACK → 发 STOP → 再读 DR。
5. **多字节接收**：前 N-2 字节随 ACK 读，倒数第二个字节前关 ACK 并发 STOP，最后一个字节读 DR。
   最后两个字节必须在临界区内一气呵成（否则中间被中断插进来会多读/漏读）。
6. **`My_I2C_ResetBus`**：关外设 → 两线切开漏输出 → 打 9 个 SCL 脉冲 → 补停止位 → 交还外设。
   依据 D8（勘误手册：从机拉死 SDA 时复位主机外设无效，必须手工补时钟）。
   **注意：这个函数在 `bsp_i2c` 内部有「硬编码 I2C2 → PB10/PB11」的映射**，
   重写时改成由配置结构传入引脚，不再硬编码。
7. **`My_I2C_MemWriteBytes` 保留**（零调用但接口完整，且 `app_mpu6050.c` 的 `reg_write` 其实用的是
   `SendBytes(0xD0, {reg, value}, 2)`，等价但更绕——将来可以切过去）。

**顺手修掉的两个隐患**：
- `app_mpu6050.c` 的 `reg_read` / `reg_write` **完全忽略返回值**，读失败时 `regValue` 初值 0 会被当真实数据用。
  这不在本次 `my_lib` 范围内，建议作为后续单独一步处理（见 Q6）。
- `My_I2C_ResetBus` 只认 I2C2，接口上却接受任意 `I2Cx`，传别的进来会静默返回。重写时明确化。

#### (d) `bsp_si2c` —— 软件 I2C，最简单也最容易写错

开漏 GPIO 位拆操作，时序参数化（不再写死 `delay(1)` / `delay(2)` 这种魔数）：

```
起始：SDA 高→低（SCL 高时）
数据：SCL 低 → 摆 SDA → SCL 高（从机在 SCL 高时采样）
应答：主机释放 SDA，读第 9 个时钟的电平；0 = ACK
停止：SCL 低 → SDA 低 → SCL 高 → SDA 高
```

**必须修掉原实现的三个 bug**（重写时一并纠正，但需要实机确认）：

1. **`My_SI2C_ReceiveBytes` 的 ACK 给反了**：写的是 `(i==Size-1) ? 1 : 0`，
   而 `ReceiveByte` 的约定是 `Ack=1 → 拉低 SDA → 回 ACK`。
   于是「最后一个字节回 ACK、中间的字节回 NAK」——**完全反了**。
   `RegReadBytes` 里写的是 `(i==Size-1) ? 0 : 1`，是对的。两份代码自相矛盾。
   （当前 `app_oled.c` 只调 `SendBytes`，所以这个 bug 还没暴露。）
2. **时钟只在「写 1」之后给延时，低电平半周期没有明确的时序保证**，
   依赖 GPIO 写入本身的耗时，高速下不可靠。重写时四个边沿都明确延时。
3. **`My_SI2C_Init` 里先写 GPIO 数据寄存器再配模式**（写 1 的时候引脚还是默认输入浮空），
   且 SCL/SDA 时钟使能代码重复了两遍。重写时顺序改正、去重。

另外 OLED 是纯写设备，`bsp_si2c` 可以只实现「写」；
但保持 `SendBytes` + `RegWriteBytes` + `ReceiveBytes` + `RegReadBytes` 四个接口完整，
以后加别的软 I2C 器件（比如 EEPROM）不用返工。

#### (e) `bsp_oled` —— 工作量最大，但可以从 1221 行砍到约 300 行

实际只需要 9 个功能：`Init` / `Clear` / `SetCursor` / `DrawString` / `Printf` /
`SendBuffer` / `StartSendBuffer` / `EndSendBuffer` ＋ 一个供 `app_oled.c` 用的驱动句柄。

- **砍掉**：画圆、填充圆、画线、矩形、位图、剪切区、文本框、光标移动、画笔/画刷、
  字体切换、`GetScreenWidth/Height`、BDF 字体引擎 —— 共 24 个函数，全是零调用点。
- **保留分段刷新**（`StartSendBuffer` / `EndSendBuffer`）：`app_oled.c` 靠它把 128 段摊到空闲时间，
  每段只占软 I2C 约 0.2 ms，**这是保护控制环周期的关键设计，必须保留**。
- **帧缓冲改成静态数组** `static uint8_t fb[128*8]`（1024 B），去掉 `malloc` 和 `pBuffer++` hack。
  ZI-data 会从 9188 涨到约 10200，20 KB RAM 完全够（余量还有约 10 KB）。
- **`OLED_Printf`**：用 `vsnprintf` 到栈缓冲，保留「不碰 `%f`」的注释警告。
- ⚠️ **`OLED_Init` 的命令序列必须按实物芯片写**（SSD1306 vs SH1106，见 Q4）。

#### (f) `bsp_font6x8`

- 换掉 BDF 那一整套：`Font_TypeDef` / `Glyph_TypeDef` 结构体、`oled_default_font.h` 的 1562 行。
- 新接口极简：`extern const uint8_t font6x8[95][8];`＋一个 `Font6x8_GetGlyph(char c)`。
- 附带把 `OLED_DrawString` 的字宽计算从「查表 + 二分」变成一次数组索引，更快。

## 6. 需要你确认的问题

**Q1. 新代码放 `bsp/` 还是原地覆盖 `my_lib/`？**
- **A（推荐）新建 `bsp/`**：新旧并存可逐块切换、可回退；代价是 `task/pid/button` 各改一行 include。
- B 原地覆盖 `my_lib/`：`user/` 侧改动最少；代价是旧实现没了，出问题不好对比，且「旧的」和「新的」在 git 里是同一个文件不好辨认。

**Q2. 函数名保持 `My_XXX` / `OLED_XXX` 不变，还是改成新命名（如 `BSP_I2C_Write`）？**
- **A（推荐）保持不变**：`user/`+`test/` 零改动，回归风险最低。函数名作为功能性标识不受著作权保护。
- B 全部改名：命名空间更干净，但要改约 40 处调用点和 10 个 `#include`，多一轮回归。

**Q3. 零调用点的接口要不要保留？**（`My_USART_ReceiveLine/ReceiveByte/ReceiveBytes`、`My_I2C_ReceiveBytes`、`My_I2C_MemWriteBytes`、`My_SI2C_ReceiveBytes/RegReadBytes/RegWriteBytes`）
- **A（推荐）保留接口**：`bsp_usart`/`bsp_i2c`/`bsp_si2c` 是通用底座，将来加有线命令行、EEPROM 不用返工，代码量增加有限。
- B 按需裁剪：只留实际用到的 11 个函数，代码最瘦，但以后要补。

**Q4.（需要看硬件）OLED 是 SSD1306 还是 SH1106？**
原代码的注释里自己写着「`0x8D` 电荷泵这条…**should be removed for SH1106**」，说明作者也不确定。
两者差异很致命（SH1106 不支持 `0x20` 寻址模式、每页 132 列需要 +2 偏移，写错就是花屏或右移 2 像素）。
**怎么确认**：看模块 PCB 上的丝印（通常印 `SSD1306` 或 `SH1106`）、或问卖家、或驱动起来看现象。
如果你不确定，我可以先按 SSD1306 写，同时把两种配置做成一个 `#define` 开关，上板一试就知道。

**Q5. `template.uvprojx` 由我直接改 XML，还是你在 Keil 里手动加文件？**
- **A（推荐）我改 XML**：加 `bsp` 分组、加 include 路径、移出旧文件，可经 git diff 审查。**前提：改之前你在 Keil 里关闭工程，否则 Keil 的未保存缓冲会把我的改动覆盖掉。**
- B 你手动加：更安全，但来回沟通成本高。

**Q6. 是否顺手修 `app_mpu6050.c` 忽略 I2C 返回值的隐患？**
`reg_read()` / `reg_write()` 现在完全不看返回值，读失败时 `regValue` 的初值 `0` 会被当成真实数据用。
这属于 `user/` 层、不在本次重构范围，但它是「I2C 一卡死就找不着北」的直接原因之一。
- A 本次不动，只完成 `my_lib` → `bsp` 的替换（**范围最清晰，推荐**）
- B 重构完成后单独一步处理（可作为下一个任务）

**Q7. 字体用哪个来源？**
- **A（推荐）自研 6×8 点阵表**：`95 × 8 = 760` 字节，自己生成自己核对，不引入任何第三方署名。
- B 用 SIL OFL 许可的开源字体（如 Inter / IBM Plex Mono）转成点阵：字形更漂亮，但需要在 `THIRD_PARTY_NOTICES.md` 里加 OFL 署名。
